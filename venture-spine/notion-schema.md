## Design Principles

1. **CQRS Pattern**: File-based state (`projects.json` + `portfolio-state.yaml`) is the write/command model. This Notion database is the read/query projection.
2. **Sync Direction**: Primarily one-way (files -> Notion). Notion priority overrides are the exception (Notion -> orchestrator).
3. **Mobile-First**: Designed so Burak can review portfolio health from his phone via Notion mobile app.
4. **Agent-Writable**: All properties are syncable via Notion MCP tools from the orchestrator loop.

## Properties

| Property | Type | Purpose | Sync Source |
|----------|------|---------|-------------|
| **Project** | Title | Project name (matches `projects.json` key) | `projects.json` |
| **Tier** | Select | `1 - Revenue`, `2 - Strategic`, `3 - Growth`, `4 - Hibernated` | `projects.json` → `tier` |
| **Lifecycle** | Select | `Ideation`, `Research`, `Architecture`, `Active Dev`, `Maintenance`, `Revenue`, `Sunset` | `project-dna.yaml` → `phase` |
| **Health** | Select | `Green`, `Yellow`, `Red` (traffic light) | `project-dna.yaml` → `health` |
| **Last Activity** | Date | Last commit or agent activity timestamp | `git log -1 --format=%ci` |
| **Open Issues** | Number | Count of open GitHub issues | `gh issue list --state open --json id -q '. \| length'` |
| **Open PRs** | Number | Count of open pull requests | `gh pr list --state open --json id -q '. \| length'` |
| **Weekly Tokens** | Number | Estimated weekly token spend | `ccusage` (when available) |
| **Budget Share** | Number | % of total budget allocated (0-100) | `projects.json` → `budget_share * 100` |
| **Day Theme** | Select | Shape Up day assignment (Mon-Fri, Flex) | Manual / `portfolio-state.yaml` |
| **Stack** | Multi-Select | Tech stack tags | `projects.json` → `tech` (expanded) |
| **GitHub Repo** | URL | Repository URL | `projects.json` → `repo` (expanded) |
| **Description** | Rich Text | One-line project description | `project-dna.yaml` → `identity` |
| **Next Action** | Rich Text | Top priority / next step | `project-dna.yaml` → `current_focus` |
| **Blockers** | Rich Text | Active blockers | `project-dna.yaml` → `blocking_issues` |
| **Type** | Select | `Client`, `SaaS`, `Internal`, `Research` | `projects.json` (manual) |
| **Stale Days** | Number | Days since last commit | `project-dna.yaml` → `days_since_last_commit` |
| **Active Workers** | Number | Running Claude Code agents | `orchestrator-tmux-state.json` (count) |
| **Project ID** | Unique ID | Auto-increment `VS-001`, `VS-002`... | Auto-generated by Notion |

## Views

| View | Type | Purpose | Configuration |
|------|------|---------|---------------|
| **All Projects** | Table | Full portfolio overview, sorted by tier | All properties visible, sorted by Tier ASC |
| **Lifecycle Kanban** | Board | Visual pipeline of project stages | Grouped by Lifecycle, shows Tier/Health/Type |
| **Revenue Projects** | Table | Tier 1 only -- revenue-critical focus | Filtered to `Tier = 1 - Revenue`, sorted by Stale Days |
| **Health Dashboard** | Board | Traffic-light health overview | Grouped by Health (Green/Yellow/Red), sorted by Tier |
| **Day Themes** | Board | Shape Up daily schedule | Grouped by Day Theme (Mon-Fri), shows next actions |
| **Active Only** | Table | Currently active projects | Filtered to `Lifecycle = Active Dev`, shows blockers |
