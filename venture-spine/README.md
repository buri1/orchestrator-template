# Venture Spine

A deterministic meta-orchestration layer for managing multiple autonomous coding projects as a solo founder. The Venture Spine sits between you (strategic decisions) and your per-project orchestrators (agent management), providing portfolio-wide visibility, budget control, and scheduling -- without being another AI agent. It is ~800 lines of shell scripts, JSON/YAML state files, and a Notion sync bridge. Zero infrastructure. Zero incremental cost.

---

## Architecture

```
LAYER 4: STRATEGIC (Human)
  Weekly review, betting table, kill decisions, client relationships
  Tools: Notion mobile, portfolio-state.yaml, morning triage output
     │
     │  reads triage / writes priority overrides
     ▼
LAYER 3: META-ORCHESTRATION (Venture Spine) ◀── you are here
  Daily triage, budget circuit breaker, DNA generation, Notion sync
  Tools: triage.sh, budget-check.sh, generate-dna.sh, sync-to-notion.sh
     │
     │  reads state files / spawns orchestrators via tmux
     ▼
LAYER 2: PER-PROJECT ORCHESTRATION (L-Thread v3)
  Issue selection, agent spawning, PR review, E2E testing
  Tools: tmux, Claude Code, git worktrees, gh CLI
     │
     │  spawns workers / reviews PRs
     ▼
LAYER 1: EXECUTION (Claude Code Workers)
  Write code, fix bugs, run tests, create PRs
  Tools: Claude Code (Opus) with --dangerously-skip-permissions
```

Key constraint: **zero cross-project agent communication**. Workers in Project A never see Project B. The Venture Spine coordinates by reading state files and spawning/killing processes (Stripe zero-coordination pattern).

## Quick Start

```bash
# 1. Run morning triage (scans all 8 registered projects)
cd venture-spine
./triage.sh

# 2. Read the output
cat daily-temperature.md

# 3. Optional: emit JSON alongside markdown
./triage.sh --json

# 4. Generate Project DNA for all projects
./generate-dna.sh

# 5. Generate DNA for a single project
./generate-dna.sh omniport-hh

# 6. Check budget against the 5-hour billing window
./budget-check.sh --verbose

# 7. Detect cross-project dependencies
./detect-deps.sh

# 8. Sync portfolio state to Notion
./sync-to-notion.sh --dry-run
```

Prerequisites: `jq`, `gh` (authenticated), `git`, `python3` (for detect-deps.sh), `npx` (for ccusage in budget-check.sh).

## File Inventory

### Scripts (executable)

| File | Purpose |
|------|---------|
| `triage.sh` | Morning health check -- polls GitHub + git for all projects, outputs `daily-temperature.md` with traffic-light health |
| `generate-dna.sh` | Auto-generates ~500-token Project DNA summaries per project from git/GitHub signals |
| `budget-check.sh` | Budget circuit breaker -- reads ccusage billing window, returns GREEN/YELLOW/ORANGE/RED with exit codes |
| `detect-deps.sh` | Scans all projects for shared dependencies (npm, infra, knowledge, git history) and writes `dependencies.yaml` |
| `sync-to-notion.sh` | CQRS bridge: pushes file-based state to Notion Portfolio Database via MCP queue |

### State Files

| File | Purpose |
|------|---------|
| `projects.json` | **Project registry** -- the source of truth for what projects exist, their paths, repos, tiers, budget shares, and day themes |
| `portfolio-state.yaml` | **Portfolio state** -- health, phase, stale days, notes, budget allocations, Shape Up cycle config, and cross-project learnings |
| `dependencies.yaml` | **Dependency graph** -- auto-generated edges (shared stack, shared infra, knowledge, git history, business dependencies) |
| `daily-temperature.md` | **Triage output** -- generated by `triage.sh`, the primary artifact the founder reads each morning |
| `daily-temperature.json` | Machine-readable triage output (generated with `--json` flag) |

## Daily Workflow

### Morning (5-10 minutes)

1. **Run triage** (or read pre-generated output if cron is configured):
   ```bash
   ./triage.sh --json
   cat daily-temperature.md
   ```
2. **Scan the traffic-light grid**: RED items need attention, OK items are autonomous.
3. **Check today's day theme**: The triage output shows which project is today's focus (Monday=omniport-hh, Tuesday=cityhub, etc.).
4. **Check budget**: `./budget-check.sh` -- GREEN means go, ORANGE means throttle, RED means pause non-Tier-1.

### Day (focused work)

5. **Launch the per-project orchestrator** for today's focus project:
   ```bash
   ./run-tmux.sh <project-dir>
   ```
6. **Let agents work**. The per-project orchestrator (Layer 2) handles issue selection, agent spawning, PR review, and E2E testing.
7. **Context switches**: If you must switch projects mid-day, read the target project's DNA first (`dna/<project>-dna.yaml`). This replaces the 20-minute "where was I?" warmup with a 30-second read.

### Evening (2 minutes)

8. **Park your context**: Update `portfolio-state.yaml` notes for the project you worked on today (what you accomplished, what's next).
9. **Optionally launch overnight agents**: Spawn autonomous agents for Tier 1 projects that can run without supervision.

## Weekly Workflow

### Friday Review (60 minutes)

1. **Run DNA refresh**: `./generate-dna.sh` -- regenerate all Project DNAs with fresh git/GitHub data.
2. **Run dependency detection**: `./detect-deps.sh` -- update the cross-project dependency graph.
3. **Review the week's triage outputs**: Were the priorities correct? Did any project get unexpectedly stale?
4. **Update portfolio-state.yaml**: Refresh health assessments, move projects between phases if needed.
5. **Sync to Notion**: `./sync-to-notion.sh` -- push latest state to the mobile-friendly dashboard.
6. **Shape Up check**: If this is the end of a 6-week cycle, run the betting table (see monthly workflow).

---

## Monthly Workflow

### Monthly Self-Assessment (60 minutes)

1. **Fill out the monthly review template**: `monthly-review-template.md`
2. **Run collection scripts** from the template to auto-populate metrics (M1-M10).
3. **Answer the 5 strategic questions** (highest-leverage action, what to stop, right project allocation, agent failures, is Venture Spine worth it).
4. **Make tier changes**: Promote or demote projects in `projects.json` based on health and revenue data.
5. **Shape Up betting table** (every 6-8 weeks): Select max 2 "full cycle" bets and 2 "maintenance" bets. Everything else is paused or hibernated.
6. **Kill zombie projects**: Any Tier 3 project that has been paused for 3+ cycles with no revenue should be killed or archived.
7. **Promote learnings**: Add cross-project patterns to `portfolio-state.yaml` learnings section.

## Configuration

### Adding a New Project

1. Edit `projects.json` and add an entry:
   ```json
   "my-project": {
     "name": "My Project",
     "path": "/Users/buraksmac/Desktop/code2/my-project",
     "repo": "buri1/my-project",
     "tier": 2,
     "lifecycle": "shaping",
     "stack": ["next.js", "supabase"],
     "description": "One-line description of the project.",
     "budget_share": 0.05,
     "day_theme": "any"
   }
   ```
2. Run `./generate-dna.sh my-project` to create the initial DNA.
3. Run `./triage.sh` to verify it appears in the health grid.
4. Add the Notion page ID to `notion-schema.md` and `sync-to-notion.sh` page mappings.

### Removing a Project

1. Set `"lifecycle": "killed"` and `"budget_share": 0.00` in `projects.json`.
2. Optionally remove the entry entirely after archiving the repo.

### Changing Tiers

1. Update the `"tier"` field in `projects.json` (1 = Revenue, 2 = Strategic, 3 = Growth).
2. Adjust `"budget_share"` proportionally. All shares should sum to 1.0.
3. Update `portfolio-state.yaml` tier summary.

### Changing Day Themes

1. Edit the `"day_theme"` field in `projects.json` (monday, tuesday, wednesday, thursday, friday, any).
2. Update `portfolio-state.yaml` meta.day_theme mapping.

## Integration Points

| System | Direction | Mechanism |
|--------|-----------|-----------|
| **Notion** | Venture Spine -> Notion | `sync-to-notion.sh` queues MCP updates; Notion is the read-optimized projection (CQRS) |
| **Notion** | Notion -> Venture Spine | Priority overrides: founder edits Notion on mobile, orchestrator reads via MCP |
| **ccusage** | ccusage -> budget-check.sh | `npx ccusage@latest blocks --active --json` provides 5-hour billing window data |
| **tmux orchestrator** | Venture Spine -> tmux | `run-tmux.sh` resolves project paths from `projects.json`; triage informs which project to launch |
| **GitHub** | GitHub -> triage.sh | `gh issue list`, `gh pr list`, `gh api` for issue counts, PR counts, CI status per project |
| **git** | git -> all scripts | Commit history for staleness, recent activity, deep-work hour calculation |
| **Chrome DevTools MCP** | Per-project | E2E testing gate (Layer 2, not Venture Spine -- but triage reports CI status) |

## Design Principles

1. **Almost 100% deterministic**: The meta-layer is shell scripts, not an LLM agent. LLM usage is ~5% (briefing generation, anomaly interpretation only).
2. **Context isolation**: Each project is a completely isolated island. No cross-project agent communication.
3. **File-based source of truth**: YAML/JSON files in git. Notion is a read-optimized projection, not the source of truth (ADR-2).
4. **Compose, don't build**: ccusage, gh CLI, Notion MCP, tmux -- thin glue layer over existing tools.
5. **Shape Up cycles**: 6-week build + 2-week cooldown. Explicit betting table. No zombie projects.
6. **The Venture Spine must justify itself**: M1 (deep-work hours) must improve within 30 days, or simplify/shut down (metrics.md kill criteria).
